# Стайлинг-центр OSNOVA — каталог стоковой окраски

React + Vite + Tailwind, данные в Supabase, фото в Cloudinary, хостинг на Vercel.

## Запуск

```
npm install
cp _env.example .env   # заполни значения
npm run dev
```

Другие команды: `npm run build`, `npm run lint` (oxlint), `npm test` (встроенный `node --test`).

## Что есть на сайте

- Категории → машина → все стоковые цвета с копированием HEX / RGB / HSL.
- Ссылка на конкретный цвет: `/vehicle/<slug>?color=<id>`. В Telegram / VK / Discord она показывает название и скрин именно этого цвета (`api/vehicle-page.js`).
- Поиск (Ctrl+K), избранное, «недавно просмотренные».
- Поиск по цвету `/color-search`: ближайшие окраски по ΔE, обзор по оттенкам, определение цвета по скриншоту (файл, вставка Ctrl+V, пипетка).
- Сравнение цветов `/compare`: до 4 окрасок рядом и таблица ΔE между парами; ссылкой можно поделиться (`/compare?c=slug:color,…`).
- «Такой же цвет у других машин» на странице цвета.
- «Ошибка в цвете?» и «Предложить машину» — репорты попадают в админку.
- Каталог кэшируется в localStorage: сайт открывается мгновенно, свежие данные подтягиваются в фоне.

## Структура

```
api/                    serverless-функции Vercel
  _lib/                 общий код (auth, db, validate, reports) — сам не становится функцией
  admin-login.js        вход админа → подписанный токен
  admin-db.js           ЕДИНСТВЕННАЯ точка записи в Supabase (токен + service_role + журнал)
  admin-audit.js        чтение журнала изменений
  admin-reports.js      очередь репортов для админки
  report.js             публичная форма репортов (со защитой от спама)
  cloudinary-sign.js    подпись загрузки фото
  vehicle-page.js       OG-теги для /vehicle/:slug[?color=…]
  sitemap.js            /sitemap.xml
sql/                    SQL для Supabase (выполняется вручную в SQL Editor)
scripts/                одноразовые скрипты (миграции, уборка, хэш пароля)
src/
  data/                 чтение каталога, тегов, стены почёта; категории — статикой
  context/              Vehicles / Tags / Favorites / Compare
  lib/                  color.js (ΔE, оттенки), compare.js, auditRollback.js, adminApi.js …
  components/, pages/   интерфейс; pages/admin — админка (отдельный чанк)
tests/                  node --test: color, textUtils, validate, auth, reports, compare, auditRollback
```

## Первая настройка базы (порядок важен)

1. `sql/vehicles-schema.sql` и таблицы тегов / стены почёта (если ещё не созданы).
2. `sql/audit-log.sql` — журнал изменений.
3. `sql/reports.sql` — репорты пользователей.
4. Деплой на Vercel с серверными переменными (см. `_env.example`).
5. `sql/lock-down-rls.sql` — закрывает запись для anon-ключа. Только после п. 4.

Репорты (`reports`) закрыты для anon полностью: пишет `api/report.js`, читает `api/admin-reports.js`.

## Переменные окружения

См. `_env.example`. Кроме перечисленных там, у формы репортов есть необязательная
`REPORT_IP_SALT` — соль для хэша IP (если не задана, берётся `ADMIN_SESSION_SECRET`).
Серверные переменные никогда не получают префикс `VITE_`.

## Админка `/admin`

Вход по имени и паролю (проверяет сервер). Разделы: добавить / редактировать машины,
теги и группы, стена почёта, **репорты**, **журнал** (у каждой записи есть кнопка «Откатить»).

Репорты: статусы «новые / принятые / отклонённые»; у ошибки в цвете — кнопка «Открыть в
редакторе» (`/admin/vehicle-editor?slug=…`). Счётчик новых репортов виден в меню.

Защита формы репортов: скрытое поле-ловушка, минимальное время заполнения, проверка, что
машина и цвет существуют, лимиты по хэшу IP (5 в час, 15 в сутки) и общий лимит
(200 в час) — считаются по самой таблице, поэтому работают между инстансами serverless.

## Как добавить машину

Через `/admin` → «Добавить машину». Формат записи в таблице `vehicles`:

```js
{
  slug: "unique-slug",
  category: "legkovoy",              // один из categories.slug
  name: "Название",
  tags: ["brand-bmw", "era-2010s"],  // id тегов из таблицы tags
  image: "https://...",
  colors: [
    { id: "white", name: "Название цвета", hex: "#FFFFFF", image: "https://..." },
    // двухцветная: hexes: ["#AAAAAA", "#BBBBBB"]
    // accentHex — необязательно, цвет вставок
  ],
}
```

## Тесты

`npm test` проверяет чистую логику: цвета и ΔE, оттенки, проверку входных данных на сервере
(`validate.js`, `reports.js`), авторизацию (подпись и срок токена, scrypt / sha256), откат
из журнала, кодирование ссылок сравнения. Компоненты тестами не покрыты.

## Уборка старых данных

После переноса машин в Supabase старую папку `src/data/vehicles/` можно удалить:

```
node scripts/cleanup-legacy-vehicles.mjs --dry-run
node scripts/cleanup-legacy-vehicles.mjs
```

Скрипт сначала сверяет старые файлы с таблицей `vehicles` и ничего не удаляет, если
хоть одной машины в базе нет.
